================================================================================
HIL DIGITAL TWIN & TELEMETRY BRIDGE - PROJECT SUMMARY & ARCHITECTURE
================================================================================

1. PROJECT ELEVATOR PITCH (FOR INTERVIEWS)
--------------------------------------------------------------------------------
"I built a Hardware-in-the-Loop (HIL) Digital Twin pipeline to bridge OT and IT 
systems. I simulated a 2-DOF robot arm's kinematics and thermal behavior in 
Python, exposed those variables over an asynchronous OPC UA server (using 
asyncua), streamed the tags via a custom gateway daemon into a containerized 
InfluxDB time-series database, and visualized the live operational telemetry 
on a Grafana dashboard managed via Docker Compose."


2. SYSTEM ARCHITECTURE & UNDER-THE-HOOD MECHANICS
--------------------------------------------------------------------------------
The setup consists of three distinct layers handling data generation, industrial 
transport, and storage/visualization:

[ LAYER 1: Kinematic & Physical Simulation ]
  - Role: Software representation of the physical robot arm.
  - Function: A Python script updates joint angles (theta_1, theta_2) using 
    sinusoidal functions, computes the tip position (X, Y) using forward 
    kinematics (trigonometry), and simulates motor heating (thermal drift).

[ LAYER 2: Asynchronous OPC UA Industrial Server ]
  - Role: Universal industrial communication protocol (standard for PLCs 
    and factory SCADA networks).
  - Function: Organizes variables into a hierarchical tree:
      Root -> Objects -> RoboticCell_1 -> Manipulator_2DOF
    Exposes metrics over an asynchronous server using Python's asyncio for 
    non-blocking I/O.

[ LAYER 3: Gateway, Time-Series DB & Visualization ]
  - Role: Real-time telemetry ingestion, storage, and visual monitoring.
  - Function:
      1. Gateway: An async Python daemon polls OPC UA tags at 10 Hz.
      2. InfluxDB: A time-series database optimized for high-write, timestamped 
         sensor data.
      3. Grafana: A web interface querying InfluxDB via Flux language every 
         1-2 seconds to render live SCADA curves.


3. DOCKER & CONTAINER ENVIRONMENT
--------------------------------------------------------------------------------
Docker provides isolated, reproducible environments so software runs identically 
without installing databases directly onto the host operating system.

[ RUNNING INSIDE DOCKER CONTAINERS ]
  1. InfluxDB Container  (Port 8086) -> Database engine storing time-series 
                                        metrics in persistent volumes.
  2. Grafana Container   (Port 3000) -> Web server displaying dashboard UI 
                                        and executing Flux queries.

[ RUNNING OUTSIDE DOCKER (HOST UBUNTU OS) ]
  - Python Scripts (opcua_bridge_server.py & opcua_to_influx.py) run directly 
    in system terminals, communicating with Dockerized services over localhost.


4. KEY TECHNICAL HIGHLIGHTS TO MENTION IN INTERVIEWS
--------------------------------------------------------------------------------
- Asynchronous I/O (asyncio): Ensures smooth 20 Hz simulation updates without 
  thread-blocking during network client reads.
- OT/IT Standardization: Implemented formal OPC UA node mapping (OT) paired 
  with modern time-series telemetry (IT).
- Production Mindset: Managed infrastructure deployment through single-command 
  container orchestration (docker compose up -d).
